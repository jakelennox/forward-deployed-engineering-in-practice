# Ask Halyard engagement charter

- Sponsor: Halyard Head of Operations, the sponsor who requested Ask Halyard; owns scope and release timing (fictitious title; name and authority to confirm). (assumption)
- Engineer: The embedded engineer (learner) owns discovery, design and the release evidence and can pause a release, but cannot grant source access or accept production use. (approval pending)
- Outcome: Staff reach the current, approved answer, with its source, faster than today. Measured as the median time from asking a question to holding the approved, cited answer, using the same agreed question set before the pilot (baseline timed in discovery) and during it, alongside the count of interruptions to colleagues asking which policy version is current; the target is set with the sponsor once the baseline exists. (assumption)
- First users: Sales and operations staff who today interrupt a colleague to find out which version of a policy is current. (approval pending)
- Not in scope: Any action on shipments or change to Halyard systems; legal advice; answers not grounded in an approved Halyard source. (approval pending)
- Decision rights: Customer security approves source access; the operations lead accepts production use; the sponsor approves scope; each source owner approves which document version is current. (approval pending)
- Evidence gate: An operations SME has reviewed the question set and expected behaviour; every answer cites its document and page or abstains; permission tests show zero leaks, document titles included, for every pilot user group. (approval pending)
- Escalation: Any access-control failure pauses the release immediately (stop condition) and goes to customer security, which signs off the fix before release resumes; scope conflicts go to the sponsor. (approval pending)
- Open assumption: Every current policy has a named authoritative owner who can say which version is approved; a policy without one stays out of the pilot. (assumption)
